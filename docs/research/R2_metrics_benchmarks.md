## 1. Как принято оценивать делинеацию ЭКГ

### 1.1. Два семейства метрик
| Семейство | Что считается | Где используется | Годится для сравнения? |
|---|---|---|---|
| **A. Точечные (fiducial-based), стандарт AAMI/CSE** | Для каждой из 6 точек (Pon, Poff, QRSon, QRSoff, Ton, Toff): Se, PPV, F1 при допуске ±150 мс и ошибка положения m ± σ (мс) на TP | Kalyakulina 2020, Moskalenko 2020, Sereda 2019, Joung 2024, ECG-CODE 2024, Jiménez-Pérez 2021/2024, torch_ecg, SEResUTer, GLF-Net | **Да, это основной язык бенчмарков LUDB** |
| B. Сегментационные (sample-wise) | Accuracy / Se / PPV по отсчётам, Dice, mIoU | SemiSegECG 2025, «Decoder Design Matters» 2026, Darmawahyuni 2023, Nurmaini 2023 | Нет: числа несопоставимы с семейством A |

**Вывод:** основная метрика берётся из семейства A. mIoU (семейство B) можно дополнительно привести для сравнения с SemiSegECG / R-U-Net, но только при совпадении их разбиения (п. 3.3).

### 1.2. Точный протокол семейства A
Источники: [Kalyakulina 2020][ludb], разд. III; [Moskalenko 2020][mosk], разд. 3.2; [ECG-CODE 2024][ecgcode], разд. 2.3.

1. **Допуск 150 мс** по ANSI/AAMI EC57:1998. Предсказанная точка — TP, если на расстоянии ≤ 150 мс есть точка разметки того же типа.
2. **FP** — предсказанная точка, рядом с которой нет точки разметки в пределах допуска. **FN** — точка разметки, не найденная алгоритмом.
3. Se = TP/(TP+FN), PPV = TP/(TP+FP), F1 = 2·Se·PPV/(Se+PPV).
4. **Ошибка** = t_pred − t_ref (мс) на каждом TP. Отчёт: среднее m и стандартное отклонение σ.
5. **Пулинг:** TP/FP/FN и ошибки суммируются по всем отведениям всех тестовых записей (micro). Kalyakulina: «computed based on the set that is pooled from the point-to-point match analysis in each single lead».
6. **Края записи:** у Moskalenko удаляются первый и последний кардиоциклы, у ECG-CODE — первая и последняя секунда. Иначе верные детекции в неразмеченных зонах считаются FP; Joung et al. этого не делали и наблюдали такие FP ([arXiv:2304.06237][joung]).
7. **Критерий CSE для точности границ** — σ ≤ 2·σ_CSE ([CSE Working Party 1985], цит. по [Kalyakulina 2020][ludb], табл. 6). Пороги 2σ_CSE: Pon 10.2 мс, Poff 12.7, QRSon 6.5, QRSoff 11.6, Toff 30.6 (для Ton не задан). Нейросетевые методы этот критерий почти никогда не выполняют: у них σ = 10–35 мс.

**Вариант сопоставления Jiménez-Pérez 2024** ([PMC11294154][jp2024]): волна считается найденной, если предсказанная точка попадает внутрь истинного интервала, и наоборот. Метрики детекции здесь считаются на уровне волны, а не точки. Наши детекции — это интервалы, поэтому этот вариант тоже легко посчитать, но для таблицы сравнения основным берём AAMI ±150 мс.

**Нюанс сопоставления.** В статьях не уточняется, используется ли сопоставление один-к-одному: AAMI-правило формально допускает, что одна истинная точка подтвердит две близкие предсказанные. Мы используем **жадное сопоставление один-к-одному** по возрастанию |ошибки|. Оно строже, и дубликаты после NMS честно уйдут в FP.

### 2.2. Что видно из таблицы
1. **QRS решён:** F1 ≈ 99.5–100% у всех современных методов. Различия — в σ (≈ 10 мс).
2. **Трудные точки — P (F1 96–98%) и Toff (σ 20–35 мс)**: на них и будут видны различия между нашими конфигурациями.
3. **⟨F1⟩ по 6 точкам у сильных методов — 98.1–99.1%.** Ориентир для нас: ≥ 98.5% в поотведенческом режиме S, сопоставимо с Moskalenko 5a (98.51) и Joung (98.84).
4. **Ни одна работа с обучением на публичном LUDB не публикует фиксированных списков разбиения.** Moskalenko обучался на закрытых данных, Sereda — 134/66 без списка, ECG-CODE — без описания. Строгого «apples-to-apples» сравнения не будет. В статье это нужно прямо оговорить и сравнивать по протоколу, максимально близкому к 5a: поотведенческий пулинг по всем 200 записям, при CV каждая запись ровно один раз в тесте.
5. Свежие работы 2025–2026 (SemiSegECG, R-U-Net «Decoder Design Matters») перешли на mIoU с фиксированным публичным разбиением 6:2:2 ([репозиторий][semiseg-gh]). Для детекционного метода это вторичная метрика.

## 3. Решения для нашего протокола

### 3.1. Как превратить детекции MyNet-1d в onset/offset
Выход модели после NMS — набор `(class, left, right, conf)` в отсчётах входа.
1. **Обратное преобразование координат:** вход — полная запись, дополненная до 5120 без ресайза (R4 §2.4), поэтому достаточно вычесть смещение паддинга (на валидации 0) и обрезать по 5000. Перевод в мс: ×2.
2. **Порог уверенности:** в отличие от mAP, метрики AAMI зависят от порога, поэтому для каждого класса берётся порог `conf_c`, максимизирующий F1 класса на **val**-части фолда. На тесте порог фиксирован. Порог IoU для NMS тоже подбирается на val (кандидаты 0.3–0.6).
3. **Устранение пересечений:** внутри отведения волны в разметке не перекрываются (R1). После NMS пересекающиеся детекции одного класса уже подавлены; пересечения разных классов (P/QRS, QRS/T) допускаются, их правка — отдельная необязательная пост-обработка, решается по результатам E2.
4. **Onset = left, offset = right** каждой оставшейся детекции класса c → точки `c_on`, `c_off`.
5. **Режим M (12 каналов):** детекция сразу даёт глобальные границы; сравнение — с агрегированной разметкой (R1 §4.1).

### 3.2. Правило подсчёта (реализуется в M3)
| Шаг | Правило |
|---|---|
| Единица оценки | (запись, отведение) в режиме S; запись в режиме M |
| Сопоставление | для каждой из 6 точек отдельно: жадное один-к-одному по возрастанию \|t_pred − t_ref\|, порог 150 мс (75 отсчётов) |
| Края | для класса c в отведении задаётся зона `[первый onset_c разметки, последний offset_c разметки]`. Детекция класса c, **центр** которой вне зоны, игнорируется (не TP и не FP). Аналог удаления крайних циклов у Moskalenko, но без ручной эвристики «кардиоцикла». Дополнительно в приложении считается вариант «без исключения» для прозрачности |
| Пулинг | micro: сумма TP/FP/FN и объединение ошибок по всем тестовым отведениям |
| Отчёт | Se, PPV, F1, m ± σ для 6 точек; ⟨F1⟩₆ и ⟨σ⟩₆; доля точек с σ ≤ 2σ_CSE |
| CV | (а) **итоговая таблица** — пулинг по объединению 5 тестовых фолдов (каждая запись один раз в тесте, ≈ протокол «все 200»); (б) mean ± SD ⟨F1⟩₆ по фолдам — для абляции |
| Доп. метрики | mAP@0.5 и mAP@0.5:0.95 по интервалам (детекционный язык, уже есть в `util.py`), F1 на уровне волн по Jiménez-Pérez, разбивка по ритмам (синус / ФП+ТП / ЭКС) |
| Тест-кейсы M3 | GT → метрики = 100%, m = σ = 0; сдвиг всех предсказаний на +10 мс → m = 10, σ = 0; сдвиг на 151 мс → Se = PPV = 0; дубль детекции → PPV < 100% |

### 3.3. Основная метрика для абляции
**Основная: ⟨F1⟩₆** — среднее F1 по шести точкам (Pon, Poff, QRSon, QRSoff, Ton, Toff) при допуске ±150 мс, сопоставление один-к-одному, пулинг по тестовому фолду.
Почему: (1) именно её считают или из неё выводятся все бенчмарки семейства A; (2) в ней отражены и пропуски, и ложные волны (важно для P при ФП); (3) torch_ecg использует макро-F1 волн как критерий выбора модели ([arXiv:2204.04420][torchecg]).

**Вторичная (обязательная в абляции): ⟨σ⟩₆** — среднее стандартное отклонение ошибки по 6 точкам, мс. Также сообщается ⟨|m|⟩₆.
Почему: F1 при ±150 мс близок к насыщению (QRS ≈ 99.9%). Разница между аугментациями может проявиться только в точности границ, а точность границ — ключевое свойство MyNet-1d (регрессия левой/правой границы).

**Предложение для A2** (окончательно фиксируется там после оценки разброса в E2): аугментация отбраковывается, если её исключение (leave-one-out) даёт
`Δ⟨F1⟩₆ ≥ +δ_F1` **или** `Δ⟨σ⟩₆ ≤ −δ_σ` при `Δ⟨F1⟩₆ ≥ 0`,
где δ_F1 = max(0.2 п.п., 1·SD⟨F1⟩₆ по фолдам/сидам baseline), δ_σ = max(0.5 мс, 1·SD⟨σ⟩₆). Порог 0.2 п.п. (а не 0.5, как в черновике TASKS) взят потому, что у сильных методов ⟨F1⟩₆ различается на 0.2–0.6 п.п. (табл. 2.1).

### 3.4. Что выносить в итоговую таблицу статьи
1. **Таблица 1 (основная, режим S):** наши Se / PPV / F1 / m ± σ по 6 точкам рядом со строками 1, 4, 5a, 5b, 6. Протокол каждой строки — в отдельном столбце.
2. **Таблица 2 (режим M, если будет):** рядом с 5c, 7, 8 (мультиотведенческие).
3. **Сноска о протоколах:** обучение на закрытых данных (5), внешний тест (6, 8, 9), отсутствие опубликованных разбиений.
4. **Приложение:** mIoU на разбиении SemiSegECG — только если останется время. Для этого нужен перевод интервалов в маску и прогон на их сплите LUDB (474 тестовых сигнала).
